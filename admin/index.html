    Eigene HTML-Seiten schützen

    Anleitung
    1. Seite auf Cloudflare Pages legen. Entweder in das Webseiten-Repo (zum Beispiel spiel/index.html) oder in ein eigenes Pages-Projekt. Die Adresse muss niklas-leidert.de oder eine Subdomain davon sein, etwa spiel.niklas-leidert.de. Eine neue Subdomain trägst du im Cloudflare-Dashboard beim Pages-Projekt unter „Custom domains" ein.
    2. Eigenes Pages-Projekt? Dann lade die Prüf-Datei herunter und lege sie dort als functions/_middleware.js ab. Im Webseiten-Repo ist sie schon drin.
    3. Diese Zeile ganz oben in den <head> einfügen und den Namen ersetzen (nur Kleinbuchstaben, Ziffern und Striche):
      <script src="https://api.niklas-leidert.de/protect.js" data-page="name-der-seite"></script>
    4. Seite einmal aufrufen. Sie erscheint unten als „wartet auf Freigabe".
    5. Freigeben: Domain eintragen, festlegen, wer sie sehen darf (alle, nur Freunde oder einzelne Accounts), dann „Freigeben".

    Nur so ist die Seite wirklich geschützt: Die Prüf-Datei liefert das HTML ohne Freigabe gar nicht aus. Liegt die Seite woanders, versteckt das Skript den Inhalt nur, der Quelltext bleibt dort abrufbar.

      Adressen unter privat.niklas-leidert.de

      Statt einer eigenen Subdomain pro Projekt: Lege einen Pfad fest, zum Beispiel privat.niklas-leidert.de/itwp. Die Seite wird dort angezeigt, der Login wird vorher geprüft. Das Projekt braucht die aktuelle Prüf-Datei aus der Anleitung oben.
